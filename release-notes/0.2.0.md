# Release notes for visfem 0.2.0

In this release, datasets are described by JSON files and drawn by built-in renderers. It adds two public example datasets, LS-DYNA and FEBio support, documentation at [visfem.de/docs](https://visfem.de/docs/), a hardened deployment and tests of the core functionality. VisFEM now requires Python 3.14.

## Added

- A data-driven dataset system. A dataset is a folder of meshes with a JSON descriptor, and an optional `render` block selects one of seven renderers: `surface`, `multi_part`, `region_id`, `scalar_field`, `timeseries`, `pvd_phase_series`, `patient_organs`. If the block is left out, the renderer is inferred from `mesh_format` and the files of the folder.
- The command line documents, scaffolds and checks datasets: `visfem renderers`, `schema`, `example <renderer>`, `new-dataset` and `validate-data`.
- `visfem fetch-ircadb` downloads the public 3D-IRCADb-01 dataset (20 patients, up to 47 organs each). `visfem fetch-openknee` downloads the Open Knee(s) specimens and the Generation 1 finite element model. The downloads resume after an interruption, replace files atomically and time out.
- Time series from flat VTK series and LS-DYNA d3plot databases, besides XDMF and PVD. FEBio 2.x models are read with `visfem.febio`.
- Playback speed control, per-region colour overrides in the Regions panel, fibre glyphs, tubes for vessel centrelines, and the MRI GRASP, CT abdomen, AVM, aneurysm, vessel tree and liver vessel datasets.
- `VISFEM_DATASETS` restricts the app to a list of datasets, and `?model=<key>` opens a dataset from a link.
- Documentation at [visfem.de/docs](https://visfem.de/docs/): installation, running the app, datasets, renderers, example data, deployment, API reference and the development guide. `llms.txt` and `llms-full.txt` are provided for agents.

## Fixed

- The Docker deployment started no sessions. The image installed no dependencies, and the command line rejected the options of the trame launcher.
- Two datasets with a series of the same name showed each other's steps, fields and colour ranges.
- Switching between categorical fields of a `scalar_field` dataset coloured the mesh by the zones of the field drawn first.
- A dataset which fails to load is reported, and the view no longer shows parts of the previous dataset. A bad dataset is skipped at startup instead of aborting the server, and the spinner no longer gets stuck after a render error.
- A colour range entered by the user survives time steps which redraw the mesh.
- Cached mesh metadata is rebuilt when the mesh is exported again. NaN and inf values no longer decide the colour range.
- XDMF series with boundary blocks load, and a static FEniCS XDMF file is read as one step.
- `validate-data` checks the files of every renderer and reports duplicate dataset keys and unreadable descriptors.
- Without `DATA_DIR`, an installed VisFEM reads `./visfem_data` instead of a folder inside its virtual environment.
- Metadata files are read as UTF-8 on Windows.

## Changed

- VisFEM requires Python 3.14 and trame 4, with the current releases of PyVista, VTK, meshio, pydantic and numpy.
- Rendering is faster: the scene is pushed to the browser once per interaction, volume meshes are skinned once, and one reader serves each XDMF time series instead of re-parsing it per frame.
- Descriptors are validated strictly. Unknown fields are errors. Every path must stay inside the datasets folder, and a dataset key may only contain letters, digits, `_`, `.` and `-`.
- Text from descriptors and file names is escaped before it reaches the browser.
- The fetch commands follow https redirects only, and the IRCADb extraction limits the size of the archive members.
- The light theme and the colours of the interface were reworked. The colour picker is a card with real buttons, and the fibre switch matches the other panel rows.

## Deployment

- The trame launcher ends a session 30 seconds after its last client disconnected; the default was 300 seconds.
- The Caddy configuration in the deployment guide rejects links which point the client to another session server. It also sends Content-Security-Policy, HSTS and nosniff headers.
- `docker-compose.yml` binds to localhost.
- `setup/requirements.txt` is exported from `uv.lock`, and a test checks that it is up to date.

## Development

- `develop` is the default branch and `main` tracks the latest release. Rulesets require a pull request and the `tests`, `ruff`, `ty` and `docs` checks.
- Type checking uses ty instead of mypy. ruff also checks docstrings, logging calls and return statements.
- The release workflow builds without permissions and publishes with only the `id-token` permission. All actions are pinned to commits and kept up to date by dependabot.
- The tests cover descriptors, discovery, mesh loading, the metadata cache, the FEBio reader, the renderers, colours, the command line, and the app without a browser on synthetic data. A warning fails a test.
